# STM32F103 双电机 CAN 通信协议

控制器使用 11 位标准 CAN ID，通信速率为 500 kbit/s。多字节整数均采用小端序，且有符号整数使用补码表示。固件默认节点 ID 为 1。

## 控制命令：`0x100 + node_id`（MP157 → F103）

| 字节 | 含义 |
| --- | --- |
| Byte 0 | 控制模式：`0` 表示停止，`1` 表示速度控制 |
| Byte 1 | 控制标志：bit 0 为电机使能，bit 1 为清除通信超时故障 |
| Byte 2～3 | A 电机目标转速，单位为 0.1 RPM，数据类型为 `int16` |
| Byte 4～5 | B 电机目标转速，单位为 0.1 RPM，数据类型为 `int16` |
| Byte 6 | 命令序号 |
| Byte 7 | 协议版本，当前固定为 `1` |

速度命令的发送间隔必须小于 300 ms。超过 300 ms 没有收到新的有效速度命令时，F103 会立即清零两路 PWM，并通过 STBY 引脚禁用 TB6612。

## 控制示例

同时使能两台电机，并将目标转速设置为正转 60.0 RPM，命令序号为 1：

```sh
canbusutil socketcan can0 101#0101580258020101
```

运行过程中建议每 100 ms 发送一次控制命令：

```sh
while true; do
    canbusutil socketcan can0 101#0101580258020101
    sleep 0.1
done
```

停止并禁用两台电机，命令序号为 2：

```sh
canbusutil socketcan can0 101#0000000000000201
```

目前固件只回显命令序号，不检查序号是否连续递增，因此周期发送相同数据帧也可以正常工作。正式上位机程序建议每发送一帧，将命令序号加 1，并允许其在 255 后回到 0。

## 状态上报（F103 → MP157）

| CAN ID | 上报周期 | 数据内容 |
| --- | --- | --- |
| `0x180 + node_id` | 100 ms | A、B 电机实际转速，使能状态，超时故障，命令序号和协议版本 |
| `0x200 + node_id` | 500 ms | A、B 两路编码器累计计数 |
| `0x700 + node_id` | 500 ms | 节点使能状态、超时故障和协议版本 |

节点 ID 为 1 时，对应的状态帧 ID 分别为 `0x181`、`0x201` 和 `0x701`。

### 转速状态帧：`0x180 + node_id`

| 字节 | 含义 |
| --- | --- |
| Byte 0～1 | A 电机实际转速，单位为 0.1 RPM，`int16` |
| Byte 2～3 | B 电机实际转速，单位为 0.1 RPM，`int16` |
| Byte 4 | 电机使能状态：`0` 为禁用，`1` 为使能 |
| Byte 5 | 通信超时故障：`0` 为正常，`1` 为已超时 |
| Byte 6 | 最近一次有效控制命令的序号 |
| Byte 7 | 协议版本 |

### 编码器位置帧：`0x200 + node_id`

| 字节 | 含义 |
| --- | --- |
| Byte 0～3 | A 电机编码器累计计数，`int32` |
| Byte 4～7 | B 电机编码器累计计数，`int32` |

### 节点心跳帧：`0x700 + node_id`

| 字节 | 含义 |
| --- | --- |
| Byte 0 | 电机使能状态 |
| Byte 1 | 通信超时故障 |
| Byte 2～6 | 保留，当前为 0 |
| Byte 7 | 协议版本 |

## 参数校准

下列参数与实际电机、减速箱和编码器有关，集中定义在 `Core/Src/motor_control.c` 文件顶部，上车前应根据实物进行校准：

- 编码器每转计数 `COUNTS_PER_REV`；
- A、B 编码器的计数方向；
- 最大允许转速 `TARGET_MAX`；
- PI 参数 `KP`、`KI`；
- 转速前馈系数 `PWM_PER_RPM`；
- PWM 每周期最大变化量 `PWM_STEP`。
